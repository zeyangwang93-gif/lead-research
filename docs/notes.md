## 2026-10-29 测试记录：Blanco（第一次负例测试）

### 问题 1：跳到了美国站
- 现象：输入 blanco.com，实际抓取的是 /us 下的页面。
- 原因：请求头的 Accept-Language 设为英语，网站据此跳转到美国英文站。
- 改进：根据目标市场设置语言，例如目标是德国就优先请求德语站；或者在 ICP 里加一个"优先站点语言"配置。

### 问题 2：证据支撑力弱
- 现象：用一句免责声明来证明"公司是德国企业"，引文真实，但支撑力不强。
- 原因：和 Meiglow 的问题 3 相同，核验只检查引文是否存在，不检查能否支撑结论。
- 改进：同问题 3。另外可以在 prompt 里要求优先引用公司地址、注册信息等直接证据。

### 问题 3：没抓到邮箱
- 现象：contact_emails 为空。
- 原因：大公司通常用联系表单，不公开邮箱；我们只用正则从网页提取邮箱。
- 改进：没有邮箱时记录联系表单页面地址；之后可以接入邮箱查找服务补充。

### 问题 4：缺少正例测试
- 现象：只测了负例，不知道能否认出真正的买家。
- 当前状态：Naber 给了 72 分，属于接近正例的难例，但还没有一个确认的进口商样本。
- 改进：建标注集时专门找确认的进口商和经销商作为正例。
## 2026-10-29 测试记录：Naber、Meiglow （第二次测试）

### 问题 1：证据和结论不一致（Naber）
- 现象：证据里有"产品从世界各地的制造商处发现"，这是对外采购的信号，但 imports_from_abroad 填了 null。
- 原因：prompt 没定义什么算"进口证据"，模型只认明确写 import 的内容。
- 改进：在 prompt 里补充定义，明确提到从海外或全球制造商采购，也算进口证据。

### 问题 2：匹配理由没有证据支撑（Naber）
- 现象："覆盖德/荷/法市场""定位中高端"两条理由，在 evidence 里找不到对应原文。
- 原因：核验只检查 evidence，不检查 match_reasons，模型可以在理由里写推测。
- 改进：要求每条理由标注引用的证据编号，程序检查编号是否存在。

### 问题 3：引文真实，但不支撑结论（Meiglow）
- 现象：结论写"向全球批发供货"，引文只说是"领先的水槽工厂"。
- 原因：核验只检查引文是否出现在原网页，不检查引文和结论是否相关。
- 改进：可以用一次额外的模型调用做相关性检查，但会增加成本，需要权衡。

### 问题 4：临时网络故障导致失败（Meiglow）
- 现象：第一次运行 ConnectError，过一会儿重跑成功。
- 原因：网站临时不可用，程序失败一次就放弃。
- 改进：抓取失败时自动重试 2–3 次，每次间隔几秒。

### 问题 5：错误信息不够具体（Meiglow）
- 现象：报错只显示 ConnectError，看不出是网址错误、网站宕机还是被拦截。
- 原因：代码只记录了异常类型，没记录异常详情。
- 改进：错误信息里加上具体原因。

## 2026-10-30 测试记录：Vango（第一次正例测试）

### 背景
产品从示例的不锈钢水槽换成户外露营帐篷，更新了 icp.json。
Vango 是英国户外帐篷品牌，品牌商通常委托工厂生产，预期应得高分。

### v1 结果：判错（假阴性）
- 分数 35，confidence low，低于 60 分线，被判为"不是客户"。

### 原因分析

#### 原因 1：prompt 规则冲突（主要原因）
- 现象：模型认为"品牌商可能自己生产"，把分数压到 35，低于评分标准中"业务和产品匹配"应得的 60 分。
- 原因：规则要求"不使用外部知识"，而"户外品牌通常找工厂代工"是行业常识，网站上不会写，模型不敢推断。
- 修改：新增规则 2a，品牌商没有提到自有工厂时，视为可能委托生产的采购方；新增规则 2b，从海外或全球制造商采购、委托生产都算进口证据（同时解决 Naber 的问题 1）。

#### 原因 2：抓错页面
- 现象：抓了赞助合作页（glenmore-lodge-partnership）和睡袋页，About 页正文为空。
- 原因：关键词 partner 太宽泛，误把赞助合作页当成贸易合作页；About 页可能是 JavaScript 渲染。
- 修改：trade 类关键词去掉 partner，加上 stockist。

#### 原因 3：核验误报
- 现象：quote_not_found 为 1，但引文其实是真的。
- 原因：模型用省略号拼接了两段原文，程序做整串匹配失败。
- 修改：verify 函数按省略号拆分引文，每段分别匹配。

### v2 结果（PROMPT_VERSION = v2）

| 项目 | v1 | v2 |
| --- | --- | --- |
| 分数 | 35 | 68 |
| 是否过 60 分线 | 否 | 是 |
| confidence | low | medium |
| 引文找不到 | 1 | 0 |
| 抓取页面 | 含赞助合作页 | 换成 Stockists 经销网点页 |

### 仍未解决的问题
1. About 页仍无正文，证据只有网页标题，JavaScript 渲染问题待处理。
2. 产品页抓的是睡袋页而非帐篷页，抓取模块不知道我们关心哪类产品。改进思路：把 icp.json 的产品关键词传给抓取模块。
3. 只验证了一个案例。放宽品牌商规则可能抬高其他公司的分数，导致误判，需要用标注集批量评估确认 v2 整体优于 v1。

## 2026-10-30 改进记录：抓取时优先选与产品相关的页面（Vango 复测）

### 改动
- schemas.py 的 ICP 新增 product_keywords（默认空列表），icp.json 填入 ["tent", "zelt", "namiot"]。
- fetcher.py 的 _pick_links：链接路径或文字含产品关键词的也算产品页，选产品页时优先选含关键词的。
- fetch_site 增加 product_keywords 参数，research.py 调用时传入 icp.product_keywords。

### 结果
- 抓取页面：首页、/about-us、/tents、/Stockists、/contact。产品页选中了帐篷页 /tents，不再是睡袋页。
- 分数 68，confidence medium，和 v2 相同；引文找不到 1 条（v2 为 0）。
- 没有单独验证 /tents 是被关键词规则选中，还是被原有的 product 规则选中。

### 瓶颈转移到内容提取
- 现象：页面选对了，分数却没变。风险项里模型自己写明"网页文本主要为导航菜单，缺乏实质内容"。
- 例子：/about-us 引用的"Airbeam Tents Awning Range Family Tent Fabrics..."是导航菜单文字，不是公司介绍；/tents 的引文"Family Poled Tents Family Camping"同样是菜单式文字。
- 原因：_to_page 只去掉了 script/style 等标签，导航、页脚没去掉，页面前部被菜单占满；加上 MAX_CHARS_PER_PAGE 截断，正文可能进不了模型的输入。About 页可能还有 JavaScript 渲染问题（见上一节）。
- 结论：选页面已经不是主要限制，现在限制效果的是页面文本的质量。
- 改进思路：
  1. 提取文本前先去掉 nav、header、footer 标签，优先取 main 或 article 区域。
  2. 先查看 About 页被截断前后的原始文本，确认正文是否真的缺失，再决定要不要上 JavaScript 渲染（如 Playwright）。
  3. 用标注集批量验证，而不是只看 Vango 一个案例。
