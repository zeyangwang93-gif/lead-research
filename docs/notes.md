## 2026-10-29 测试记录：Blanco（第一次负例测试）

### 问题 1：跳到了美国站
- 现象：输入 blanco.com，实际抓取的是 /us 下的页面。
- 原因：请求头的 Accept-Language 设为英语，网站据此跳转到美国英文站。
- 改进：根据目标市场设置语言，例如目标是德国就优先请求德语站；或者在 ICP 里加一个"优先站点语言"配置。

### 问题 2：证据支撑力弱
- 现象：用一句免责声明来证明"公司是德国企业"，引文真实，但支撑力不强。
- 原因：和 Meiglow 的问题 3 相同，核验只检查引文是否存在，不检查能否支撑结论。
- 改进：同问题 3。另外可以在 prompt 里要求优先引用公司地址、注册信息等直接证据。

### 问题 3：没抓到邮箱
- 现象：contact_emails 为空。
- 原因：大公司通常用联系表单，不公开邮箱；我们只用正则从网页提取邮箱。
- 改进：没有邮箱时记录联系表单页面地址；之后可以接入邮箱查找服务补充。

### 问题 4：缺少正例测试
- 现象：只测了负例，不知道能否认出真正的买家。
- 当前状态：Naber 给了 72 分，属于接近正例的难例，但还没有一个确认的进口商样本。
- 改进：建标注集时专门找确认的进口商和经销商作为正例。
## 2026-10-29 测试记录：Naber、Meiglow （第二次测试）

### 问题 1：证据和结论不一致（Naber）
- 现象：证据里有"产品从世界各地的制造商处发现"，这是对外采购的信号，但 imports_from_abroad 填了 null。
- 原因：prompt 没定义什么算"进口证据"，模型只认明确写 import 的内容。
- 改进：在 prompt 里补充定义，明确提到从海外或全球制造商采购，也算进口证据。

### 问题 2：匹配理由没有证据支撑（Naber）
- 现象："覆盖德/荷/法市场""定位中高端"两条理由，在 evidence 里找不到对应原文。
- 原因：核验只检查 evidence，不检查 match_reasons，模型可以在理由里写推测。
- 改进：要求每条理由标注引用的证据编号，程序检查编号是否存在。

### 问题 3：引文真实，但不支撑结论（Meiglow）
- 现象：结论写"向全球批发供货"，引文只说是"领先的水槽工厂"。
- 原因：核验只检查引文是否出现在原网页，不检查引文和结论是否相关。
- 改进：可以用一次额外的模型调用做相关性检查，但会增加成本，需要权衡。

### 问题 4：临时网络故障导致失败（Meiglow）
- 现象：第一次运行 ConnectError，过一会儿重跑成功。
- 原因：网站临时不可用，程序失败一次就放弃。
- 改进：抓取失败时自动重试 2–3 次，每次间隔几秒。

### 问题 5：错误信息不够具体（Meiglow）
- 现象：报错只显示 ConnectError，看不出是网址错误、网站宕机还是被拦截。
- 原因：代码只记录了异常类型，没记录异常详情。
- 改进：错误信息里加上具体原因。
